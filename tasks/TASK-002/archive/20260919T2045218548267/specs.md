Это предложение требуется включить в представляемый план, а не подменять молча запрошенный механизм. Сохранение ключа не означает подтверждение его валидности провайдером.

Загружать только id/title/updatedAt, без JSON: https://developer.android.com/training/data-storage/room/accessing-data . Состояния загрузки, пустого результата и ошибки чтения с повтором.
4. Чат (AC4, AC8): LazyColumn сообщений с ключами, пузырьки пользователя/ассистента, нижняя строка ввода с учётом клавиатуры, индикатор ожидания, доступные подписи кнопок. Только одна активная отправка. Интеграция DeepSeek — целый ответ без streaming, явный повтор без дублирования user-сообщения, отмена при подтверждённом выходе, никакого автоматического retry POST. Контракт, модель и сетевое поведение определены ниже.
5. Хранение (AC3, AC5–6): Room/SQLite, chats(id TEXT PRIMARY KEY, title TEXT, createdAt, updatedAt, contextJson TEXT). JSON с собственной schemaVersion и сообщениями (id, role, content); не сохранять API-ключ и транспортные DTO. Одна актуальная копия сообщений, без повторяющихся снимков контекста каждого запроса. Репозиторий выдаёт доменные модели, DAO/entity остаются impl. Начальная схема v1 экспортируется; destructive migration запрещена.
6. Выход (AC5–6): Back/стрелка → «Сохранить чат?» → «Да» или «Нет». Закрытие модалки возвращает в чат. На «Нет» новый чат отбрасывается; прежняя версия остаётся неизменной (ответ заказчика 2026-09-19). Сохранения при сворачивании и process death нет. Поворот не считается выходом. Предложение для пустого чата: «Да» сохраняет его с темой «Новый чат».

Оценка JSON: подходит для небольшого MVP со снимком всего чата. Например, 1000 сообщений по 1 КиБ текста — около 1 МиБ полезного текста плюс JSON и SQLite; это оценка, не измерение. ## Уточнения окончательного плана

Все пункты относятся к user story в analysis.md. Вне scope: аккаунты, синхронизация, вложения, редактор ассистента, экспорт, поиск по сообщениям, UI выбора моделей и публикация.

S4 / AC8. В core:llm:api контракт:
```kotlin
interface Llm {
    suspend fun execute(request: LlmRequest): LlmResult
}
```
LlmRequest — неизменяемый список LlmMessage(role, text), роли system/user/assistant. LlmResult — Success(text, finishReason) или Failure(domainError). Ошибки: Unauthorized, InsufficientBalance, RateLimited, Network, Timeout, ContextTooLarge, ModelUnavailable, ProviderUnavailable, InvalidResponse, InvalidRequest. CancellationException пробрасывается. В контракте нет ключа, Ktor, Room и DeepSeek DTO. DeepSeekLlm в core:llm:impl получает конфигурацию модели и защищённое хранилище через DI; feature:chat зависит только от api. Смена провайдера — binding Llm в Koin, смена модели — конфигурация реализации. Fake Llm в тесте доказывает заменяемость.

DeepSeek: Ktor POST https://api.deepseek.com/chat/completions, model=deepseek-flash, stream=false, thinking.type=disabled, max_tokens=2048. Официальные источники проверены 2026-09-19: https://api-docs.deepseek.com/ и https://api-docs.deepseek.com/api/create-chat-completion/ . Модель из актуального quick start. Пользовательских system prompt пока нет. Connect timeout 15 с; request/socket 120 с; автоматический retry POST отключён. Непустой ответ с finish_reason=length отображается с отметкой ограничения, пустой/повреждённый ответ — ошибка. Сырые ошибки API не выводятся. При превышении контекста — понятная ошибка и предложение нового чата, без молчаливого обрезания истории. Защитный предел запроса 1 МиБ UTF-8 сериализованного JSON; он не является оценкой токенов.

S2 / AC1,7. Зашифрованные preferences через Keystore/AES-GCM включены в предлагаемый план вместо deprecated класса EncryptedSharedPreferences. Уникальный IV при каждой записи. Предусмотреть замену ключа с главной и при ошибке авторизации, сохраняя рабочую сессию в памяти. Ключ вводится только в приложении, не в переписке. История не удаляется при смене ключа.

S3 / AC2,3. Тема — первые 60 Unicode code points первого сообщения, переносы заменяются пробелами; пустой чат — «Новый чат». Сортировка updatedAt DESC, при равенстве — ID. Это предлагаемые настройки в составе плана.

S4–5 / AC4–6. До завершения/повтора ошибочной отправки новая отправка блокируется. Поворот сохраняет компонент и запрос в памяти. Home не вызывает модалку. При подтверждённом выходе запрос отменяется, поздний callback игнорируется по request ID. На «Да» pending превращается в interrupted до сохранения. JSON дополнительно хранит deliveryState и finishReason для корректного повторного открытия и retry; transport DTO не сохраняются. Повреждённая/неизвестная версия JSON показывает ошибку, не перезаписывается. Пустой чат при «Да» сохраняется. Отмена модалки оставляет пользователя в чате. Process death не сохраняет черновик.

JUnit и имитация сетевого адаптера, Android Room/Keystore/Compose проверки и APK. Реальный smoke test требует ключа, введённого в приложении; без него проверка BLOCKED.
