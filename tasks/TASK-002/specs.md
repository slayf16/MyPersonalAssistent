## S2. Ввод и защита ключа — AC1,7
Маскированный input, пустой ключ запрещён. AES-GCM, ключ шифрования в Android Keystore, ciphertext и новый случайный IV каждой записи — private SharedPreferences, исключённые из backup/переноса. EncryptedSharedPreferences deprecated, поэтому предлагается платформенная реализация зашифрованных preferences: https://developer.android.com/reference/androidx/security/crypto/EncryptedSharedPreferences ; https://developer.android.com/privacy-and-security/keystore . История/прочие настройки — Room. Ошибка хранения: snackbar «Техническая ошибка», остаться на форме; ошибка чтения ключа позволяет ввести заново. Сохранение не означает проверку у провайдера. Замена ключа доступна с главной. Ключ вводится в приложении, не в переписке/логах.

## S4. LLM, анимация и ошибки — AC3,4,8
core:llm:api:
```kotlin
interface Llm {
    suspend fun execute(request: LlmRequest): LlmResult
}
```
LlmRequest содержит immutable messages(role, text); роли system/user/assistant. LlmResult: Success(text, finishReason) или Failure(domainError). CancellationException пробрасывается. Контракт не раскрывает ключ, Ktor/DeepSeek DTO и Room. DeepSeekLlm в core:llm:impl получает ключ и конфигурацию модели через DI; app связывает Llm в Koin. Другой провайдер заменяет binding, другая модель — конфигурацию, feature:chat не меняется.

Ktor POST https://api.deepseek.com/chat/completions; model=deepseek-flash, stream=false, thinking.type=disabled, max_tokens=2048. Проверенные 2026-09-19 источники: https://api-docs.deepseek.com/ и https://api-docs.deepseek.com/api/create-chat-completion/ . Без system prompt в первом варианте. Connect timeout 15 с, request/socket 120 с; автоматический retry POST отсутствует. Внутренние ошибки: авторизация, баланс, лимиты, сеть/таймаут, контекст, модель/провайдер, некорректный ответ. Пользователю единый snackbar «Техническая ошибка», без сырых ошибок/секретов. История контекста не обрезается молча; защитный предел сериализованного запроса 1 МиБ (не оценка токенов). finish_reason=length с непустым текстом показывается как ограниченный ответ, пустой/повреждённый ответ считается ошибкой.

Compose: LazyColumn пузырьков сообщений, нижний input с учётом клавиатуры. Отправка атомарно переносит исходный текст в user-пузырёк и очищает input. Пока выполняется execute, input и отправка заблокированы, под сообщением один временный assistant-пузырёк с циклической анимацией трёх точек. Accessibility-описание «Ассистент отвечает», без озвучивания каждого кадра. Пузырёк ожидания не является сообщением контекста/БД. На успехе он заменяется ответом. Анимация прекращается при завершении, ошибке и уходе с экрана.

При ошибке: убрать ожидание, удалить только текущий неуспешный user-turn из рабочей истории, вернуть его исходный текст в input, разблокировать редактирование/отправку, выдать ровно один одноразовый snackbar «Техническая ошибка». Перерисовка не повторяет snackbar. Повтор — обычная отправка возвращённого/отредактированного текста, без дублей. Предыдущие успешные сообщения сохраняются; тема пересчитывается по оставшейся истории. Это конкретное предлагаемое поведение исключает потерю нового черновика и дубль в контексте. Cancellation при выходе не показывает техническую ошибку.

MVI: неизменяемый State и Intent, snackbar через Effect; один активный request ID. Scope принадлежит Decompose-компоненту, поворот удерживает сессию и запрос. Поздние callbacks отменённого запроса игнорируются.

## S5. Единая БД и сохранение — AC5–7
core:dataBase:impl единолично владеет RoomDatabase, entities, DAO, созданием и миграциями. Koin single с applicationContext создаёт одну БД на процесс приложения; app регистрирует модуль один раз. Ни feature, ни другие core не вызывают Room.databaseBuilder.
core:dataBase:api предоставляет интерфейс ChatStorage: observeSummaries(), read(id), upsert(record), нейтральные storage-record модели без Room-аннотаций/DAO и зависимости от core:history. core:history:impl зависит от собственного api и core:dataBase:api, преобразует JSON в доменную историю. Нет impl→чужой impl и циклов. Feature используют core:history:api. Идентичность экземпляра проверяется через два разрешения из одного Koin application.

Room schema v1: chats(id TEXT PRIMARY KEY, title TEXT, createdAt, updatedAt, contextJson TEXT). JSON schemaVersion=1, messages(id, role, content, deliveryState, finishReason при необходимости). Не дублировать полные снимки контекста для каждого сообщения. Экспорт схемы, destructive migration запрещена. Повреждённый/неизвестный JSON — ошибка без перезаписи. Чтение/сериализация/запись вне UI-потока.

Back/стрелка → «Сохранить чат?» с «Да»/«Нет», в том числе пустой чат. Закрытие модалки возвращает в чат. «Да»: отменить текущий запрос, сохранить согласованный снимок атомарным upsert, открыть главную после успеха. Незавершённое user-сообщение при таком выходе хранится как interrupted, ожидание не хранится; при открытии переносится в input и удаляется из рабочей истории по аналогии с ошибкой, без автоматического запроса и snackbar. На сбое записи остаться в чате, snackbar «Техническая ошибка», дать повторить сохранение или отказаться; input не заменять текстом, поскольку execute здесь не ошибался. Пустой чат сохраняется как «Новый чат». Повторные нажатия во время записи заблокированы.
«Нет»: отменить запрос, отбросить рабочую копию, открыть главную; прежняя версия остаётся. Записей при отправке, Home, повороте и process death нет. Черновик input не входит в сохраняемую историю. После уничтожения процесса остаётся последний подтверждённый снимок.
