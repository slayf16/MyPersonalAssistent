## Практические уточнения в пределах утверждённого плана

- `DeepSeekLlm` должен получать ключ через внедрённый credential provider/repository в момент `execute`, а не хранить plaintext-ключ в singleton или фиксировать его при создании DI-графа. Тогда замена ключа с главной применяется к следующему запросу без пересборки графа и не расширяет публичный контракт `Llm`.
- При выборе «Да» во время генерации сначала отменить запрос и дождаться завершения его job (или атомарно закрыть request ID), затем сформировать снимок. Поздний callback не должен дописать ответ после определения сохраняемого снимка; незавершённый user-turn сохраняется как `interrupted` по S5.
- Ошибку расшифровки ключа трактовать как недоступный credential: история остаётся нетронутой, пользователь возвращается к форме ключа. Не удалять ciphertext автоматически и не выводить причину/ключ в лог.
- Проверку прямых зависимостей из S1 выполнить до первого добавления каждой зависимости и зафиксировать в `docs/DEPENDENCIES.md`; отсутствие подтверждённых GitHub stars/licence является блокером только для соответствующей зависимости, а не основанием молча менять утверждённый стек.

Официальная документация DeepSeek на дату проверки подтверждает предусмотренные планом `model=deepseek-flash`, `stream=false` и `thinking.type=disabled`; сетевой контракт S4 можно реализовывать без изменения плана.
