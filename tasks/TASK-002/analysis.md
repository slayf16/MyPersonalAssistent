# TASK-002 — уточнённый анализ

User story: пользователь вводит ключ, создаёт текстовые чаты с реальными ответами DeepSeek, открывает локальную историю и решает, сохранять ли изменения при выходе.

Подтверждённые требования из текущего диалога 2026-09-19:
- Главная: LazyColumn тем, текст «Можете начать создавать своего ассистента.», FAB с плюсом справа внизу.
- Перед главной ввод API-ключа и зашифрованные preferences.
- Чат как в мессенджере, реальный DeepSeek через интерфейс Llm с методом execute, заменяемый через DI.
- История SQLite по ID и JSON; запись только по «Да» в диалоге «Сохранить чат?». «Нет» отбрасывает новые изменения, прежняя версия остаётся.
- «Пока идет генерация ответа показывать анимацию в пузырике многоточие».
- При ошибке возвращать запрос в input и показывать snackbar «Техническая ошибка».
- «БД делать в коре модуле, создать отдельный модуль dataBase, дальше по правилам, экземпляр бд должен быть синглтоном на проект».
- «И полностью переписать Ридми гита, с описанием структуры андроид проекта».

AC1: без ключа форма ввода, главная только после успешной защищённой записи; ошибка расшифровки не удаляет историю.
AC2: точное пустое состояние и FAB; LazyColumn сохранённых тем, открытие контекста по ID.
AC3: сообщения по ролям, input снизу; во время запроса пузырёк с анимированным многоточием; двойная отправка заблокирована.
AC4: ошибка генерации убирает ожидание, возвращает исходный текст в редактируемый input, выдаёт один snackbar «Техническая ошибка»; повтор не дублирует сообщение в контексте.
AC5: Back/стрелка показывают модалку; «Да» upsert и выход только после успеха; «Нет» сохраняет предыдущую версию; ошибка записи оставляет чат открытым.
AC6: до «Да» записи истории нет; поворот не теряет текущую сессию; process death оставляет только последний подтверждённый снимок.
AC7: один экземпляр Room DB на процесс приложения, создаваемый в core:dataBase:impl, api не раскрывает Room DAO/entity; секреты не попадают в БД/логи/backup.
AC8: реальный ответ через Llm.execute; замена реализации в DI без изменения feature:chat; отмена не ошибка.
AC9: README полностью описывает фактическое дерево Android-модулей, обязанности, зависимости, настройку, сборку, тесты и поведение сохранения.

Предложения в составе плана: AES-GCM/Keystore для preferences, без streaming, тема из первых 60 символов первого сообщения. Пока запрос выполняется, ввод блокируется, чтобы возврат текста не перетёр другой черновик. Ошибочный user-turn откатывается из рабочей истории и становится черновиком. Это включено в план для утверждения.
