# Узкая QA-проверка основного MCP-потока TASK-014

Дата: 2026-09-29.

Заказчик задал приоритет проверки:

> «проверяй основной флоу, остальное в туду. я тебе давал эмулятор с нужным ключом, на нем проверяй»

В результате для TASK-014 четыре уже зарегистрированных API-36 device-test
finding перенесены в локальный `tasks/TASK-014/qa-todo.md`; их исходный отчёт
`tasks/TASK-014/tests-cycle3-full-qa.md` сохраняется с `Outcome: FAIL`.

Проверка направлена на исходный `Pixel_9_Pro` API 36 и его сохранённый ключ
DeepSeek. Она не разрешает удалять или очищать приложение, менять userdata,
экспортировать ключ либо восстанавливать snapshot. Fresh install не считается
эквивалентом проверки исходного provisioned state.

Это решение меняет приоритет QA, но не делает неисполненные проверки PASS и
не отменяет установленную project-wide targetSdk-only матрицу.
